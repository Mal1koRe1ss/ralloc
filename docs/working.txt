[CORE-CONCEPTS]

    [HEAP-VS-STACK]
    We are going to use Heap, because the main concept is dynamic memory.
    Stack -> static
    Heap -> dynamic

    [SYSTEM-CALLS-FOR-MEMORY-MANAGE]
    `sbrk / brk` are used to resize the data segment of a proccess. It'll increment the program break and return the previous addr.
    `mmap` used to map files or devices into memory. The other reason is to allocate large places in da memory. It's more flexible than `sbrk`

    [FRAGMENTATION]
    Internal Fragmentation : wasted space within an allocated block (due to alignment)
    External Fragmentation : wasted space between allocated blocks, but it can make it hard to allocate large contiguous chunks in the memory.

    [ALLOCATION-STRATEGIES]
    First case : Allocate the first block large enough. Fast but can lead to fragmentation.
    Best case : Allocate the smallest that's large enough. Reduces fragmentation but slower.
    Worst case : Allocate the largest block. Can help reduce fragmentation in some cases.
    Buddy case : Allocate blocks in sizes that are powers of two (2,4,8,16... etc.). Easy to merge free blocks but can lead to internal fragmentation.

    [DATA-STRUCTURES-FOR-TRACKING-MEMORY]
    Free List : A linked list of free memory blocks. Common and simple for implementing.
    Bitmaps : Used in slab allocators to track free or used blocks.
    Circular Linked Lists : Efficient for managing free blocks.

[STEPS-FOR-BUILDING-A-CUSTOM-ALLOC]
    1. We need to understand how `malloc`, `free` and `realloc` works. Their working behavior are the blueprint.
    2. We are going to choose a allocation strategy; Whether it's free list, buddy case or another method. Each has differences between speed, fragmentation and overhead.
    3. Implementing core functions; `custom_malloc(size_t size)` should return a pointer to a block of memory of **at least** `size` bytes. `custom_free(void *ptr)` should reclaim the allocated memory. Lastly `custom_realloc(void *ptr, size_t size)` should resize an existing alloc.
    4. Handling system calls; AI thinks that we can use `sbrk` or `mmap` for requesting memory from the OS(kernel), for small allocs `sbrk` might be enough but for large ones `mmap` is better.
    5. Testing; We should write tests to check for fragmentation, alignment issues & performance.
